ТЕКУЩИЙ СТАТУС ПОДКЛЮЧЕНИЯ
Отдельный сервер Netlify опубликован. Живые проверки preflight/CORS
и отклонения пустой заявки прошли. Переменные Mailtrap добавлены пользователем.
Письмо из кнопки Send Test в Mailtrap получено пользователем.
Полная доставка заявки из формы портфолио в Gmail ещё не проверена.

Сейчас используется демонстрационный домен Mailtrap demomailtrap.co.
Он позволяет отправлять письма только на адрес регистрации аккаунта Mailtrap.
Получатель текущего тестового подключения: amdevelopersgroup@gmail.com.
Для обычной отправки потребуется подтвердить собственный домен в Mailtrap.

Форма показывает успех только после подтверждения сервером принятия письма
Mailtrap. Это не подтверждает попадание письма во «Входящие»: после настройки
проверьте журнал Mailtrap и папки «Входящие»/«Спам» Gmail.
При ошибке поля сохраняются и появляется ссылка с заполненным черновиком Gmail.
Отправку черновика пользователь завершает вручную.
Повторная отправка во время запроса блокируется, ожидание ограничено 20 секундами.
Сервер проверяет поля и ограничивает частоту запросов.

ПУБЛИКАЦИЯ ПОРТФОЛИО
1. В аккаунте amdevelopersgroup создайте репозиторий amdevelopers-portfolio.
   Выберите Public и включите Add README.
2. Распакуйте этот архив. Через Add file → Upload files загрузите прямо
   в корень репозитория index.html, script.js, styles.css, README.md,
   README.txt и папку assets. Зафиксируйте загрузку в ветке main.
3. Откройте Settings → Pages. Выберите Deploy from a branch,
   ветку main и папку /(root), затем нажмите Save.
4. Дождитесь успешного завершения публикации во вкладке Actions.
5. Откройте https://amdevelopersgroup.github.io/amdevelopers-portfolio/
   и отправьте пробную заявку. Проверьте Gmail, включая папку «Спам».
При локальном открытии index.html доступен черновик Gmail; автоматическая
отправка работает только с опубликованного разрешённого адреса.

РАЗРЕШЁННЫЙ АДРЕС ПОРТФОЛИО
https://amdevelopersgroup.github.io
Новый путь /amdevelopers-portfolio/ не требует изменения разрешённого origin.
При переходе на другой домен добавьте его HTTPS-origin в серверную переменную
CONTACT_ALLOWED_ORIGINS и заново опубликуйте сервер. Указывается адрес без пути
и завершающего слеша, например https://example.com.
